## はじめに

[前回](../20260706-astro-layouts/)でレイアウトコンポーネントを作り、記事ページに`<head>`が入って文字化けが直りました。ただ、見た目は素のHTMLのままです。今回はスタイリング環境としてPanda CSSを導入します。

Panda CSSを採用すること自体は[第3回](../20260627-adr/)のADRで決定済みです。Tailwind CSSやCSS Modulesと比較してなぜPanda CSSにしたのかは、そちらに書きました。この記事では導入の手順と、実際に入れてみて気づいた点を記録します。

### この記事に登場するライブラリのバージョン

```json
  "dependencies": {
    "astro": "^7.0.0",
```

## Panda CSSとは

Panda CSSは、ビルド時にCSSを生成するCSS-in-JSライブラリです。TypeScriptで書いたスタイル定義を静的解析し、実際に使われているスタイルだけをCSSファイルとして出力します。ブラウザに送られるのは生成済みのCSSだけで、ランタイムのJavaScriptは含まれません。

ADRで「ゼロランタイムなCSSを志向する」という方針を立てていたので、そこに合う選択肢でした。

## インストール

devDependencyとして追加し、初期化コマンドを実行します。

```bash
npm install -D @pandacss/dev
npx panda init --postcss
```

`--postcss`を付けると、PostCSS経由でPandaを動かすための設定まで生成されます。生成されるのは次の3点です。

- `panda.config.ts`（Pandaの設定ファイル）
- `postcss.config.cjs`（PostCSSの設定ファイル）
- `package.json`の`prepare`スクリプト

## エントリーとなるCSSは1行だけ

Pandaが生成したCSSを読み込むためのファイルを作ります。`src/index.css`を作成しましたが、中身はこの1行だけです。

```css
@layer reset, base, tokens, recipes, utilities;
```

PostCSSプラグインがこのファイルを処理するときに、各レイヤーへ生成したCSSを流し込む仕組みです。自分で書く必要があるのは、レイヤーの並び順の宣言だけということになります。

`@layer`はCSSのカスケードレイヤーで、宣言した順序がそのまま優先順位になります。後に書いたレイヤーほど優先度が高くなるため、この順序だと次のようになります。

| レイヤー | 内容 | 優先度 |
| --- | --- | --- |
| `reset` | ブラウザ既定のスタイルのリセット | 最も低い |
| `base` | `globalCss`で指定した全体のスタイル |  |
| `tokens` | デザイントークンのCSS変数 |  |
| `recipes` | レシピで定義した部品のスタイル |  |
| `utilities` | `css()`で個別に書いたスタイル | 最も高い |

個別に書いたスタイルがリセットや全体設定に意図せず上書きされないことが、この1行で保証されます。

あとは`RootLayout.astro`でこのファイルをimportすれば読み込まれます。

```astro
---
import "../index.css";
---
```

## リセットCSSは設定で有効にする

`panda.config.ts`の`preflight`を`true`にすると、リセットCSSが`reset`レイヤーに入ります。

```ts
export default defineConfig({
  preflight: true,
  // ...
});
```

別途リセットCSSのライブラリを入れる必要はありませんでした。

## `.astro`と`.svelte`をincludeに追加する

初期化直後の`include`は`.js`・`.jsx`・`.ts`・`.tsx`だけを対象にしています。このままだと`.astro`や`.svelte`の中に書いたスタイルが解析されず、CSSが生成されません。拡張子を追加しました。

```ts
  include: [
    "./src/**/*.{ts,tsx,js,jsx,astro,svelte}",
    "./pages/**/*.{ts,tsx,js,jsx,astro,svelte}",
  ],
```

Pandaは「実際に使われているスタイルだけ」を出力するため、解析対象から外れているファイルは存在しないものとして扱われます。スタイルが当たらないときは、まずここを疑うことになりそうです。

[第4回](../20260628-biome/)でBiomeを導入したときも、`overrides`で`.svelte`と`.astro`を対象に含める必要がありました。Astro + Svelteという構成では、ツールに対象ファイルを教える作業が繰り返し出てきます。

## 生成物はGit管理下に置かない

`panda codegen`を実行すると、プロジェクトルートに`styled-system`ディレクトリが生成されます。中身は`css`・`patterns`・`recipes`・`tokens`・`types`などで、ここから`css()`などの関数をimportして使います。

これは生成物なので、`.gitignore`に追加しました。

```text
## Panda
styled-system
styled-system-studio
```

Git管理から外すと「cloneした直後はimport先が存在しない」という状態になりますが、`panda init`が登録してくれた`prepare`スクリプトがこれを解決します。

```json
  "scripts": {
    "prepare": "panda codegen"
  }
```

`prepare`は`npm install`や`npm ci`の後に自動実行されるnpmの仕様上のスクリプトです。依存関係をインストールすれば生成物も一緒に用意されます。GitHub Actions側でも`withastro/action`が依存関係のインストールを行うため、追加の設定は不要でした。

## 設定ファイルを分割する

`panda.config.ts`には、デザイントークン・パターン・レシピ・グローバルCSSなど、性質の異なる設定をすべて書けます。このブログでは`src/panda/`に分けてimportする形にしました。

```text
src/panda/
  ├ global.ts          … globalCss（全体に効かせるスタイル）
  ├ patterns.ts        … 自作パターン
  ├ semantic-tokens.ts … セマンティックトークン
  ├ slot-recipes.ts    … スロットレシピ
  ├ textStyles.ts      … テキストスタイル
  ├ tokens.ts          … デザイントークン
  └ utilities.ts       … 自作ユーティリティ
```

`panda.config.ts`は、それらを集約する場所になりました。

```ts
import { defineConfig } from "@pandacss/dev";
import globalCss from "./src/panda/global";
import { flex, layoutInner, tagList } from "./src/panda/patterns";
import semanticTokens from "./src/panda/semantic-tokens";
import { tagStyle } from "./src/panda/slot-recipes";
import textStyles from "./src/panda/textStyles";
import tokens from "./src/panda/tokens";
import utilities from "./src/panda/utilities";

export default defineConfig({
  preflight: true,
  include: [
    "./src/**/*.{ts,tsx,js,jsx,astro,svelte}",
    "./pages/**/*.{ts,tsx,js,jsx,astro,svelte}",
  ],
  exclude: [],
  globalCss,
  theme: {
    extend: {
      breakpoints: { md: "600px" },
      tokens,
      semanticTokens,
      textStyles,
      slotRecipes: { tagStyle },
    },
  },
  patterns: {
    layoutInner,
    tagList,
    extend: { flex },
  },
  conditions: {
    light: "[data-color-mode=light] &",
  },
  utilities: {
    extend: utilities,
  },
  outdir: "styled-system",
});
```

`defineTokens`や`definePattern`といった定義用の関数が用意されているので、分割したファイル側でも型の補完が効きます。それぞれの中身は次回以降に書きます。

## 書いてみる

ヘッダーのタイトル部分はこのように書きました。

```astro
---
import { css } from "../../styled-system/css";

const title = css({
  fontSize: "2xl",
  fontFamily: "title",
  fontWeight: "bold",
  color: "lime.500",
  _light: {
    color: "cyan.500",
  },
});
---

<a class={title} href={`${import.meta.env.BASE_URL}/`}>blog.naska.dev</a>
```

`css()`はクラス名の文字列を返す関数なので、`class`属性にそのまま渡します。ビルド後のHTMLを確認すると、以下のように出力されていました。

```html
<a class="fs_2xl ff_title fw_bold c_lime.500 light:c_cyan.500" href="/study-blog/">blog.naska.dev</a>
```

プロパティごとに1つのクラスが割り当てられる、アトミックなCSSになっています。同じ`fontSize: "2xl"`を別の場所で書いても、生成されるCSSは`fs_2xl`の1つだけです。

なお`_light`は、Pandaが既定で用意している条件のセレクタを`conditions`で上書きしたものです。これについては次回詳しく触れます。

## まとめ

- `npx panda init --postcss`で設定ファイルが一通り生成される
- エントリーCSSは`@layer`の順序を宣言する1行だけでよい
- `include`に`.astro`と`.svelte`を追加しないと、スタイルが生成されない
- 生成物の`styled-system`はGit管理から外し、`prepare`スクリプトで自動生成する

これでスタイルを書く準備ができました。次回はデザイントークンとセマンティックトークンの設計について書きます。

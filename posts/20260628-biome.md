# BiomeをAstro+Svelteプロジェクトに導入する

## はじめに

ブログ開発の続きです。今回はBiomeを導入しました。

ESLintとPrettierの組み合わせが一般的ですが、動作の遅さが気になっていました。BiomeはRustで実装されていて実行が速く、また2.4でAstroやSvelteのサポートが強化されたとのことで、試してみることにしました。（まだExperimentalです。）

### この記事に登場するライブラリのバージョン

```json
"devDependencies": {
  "@biomejs/biome": "2.5.1"
}
```

## Biomeとは

Biomeは、JavaScriptやTypeScriptを中心としたWebフロントエンド向けのツールチェーンです。

ESLintのようなリンターとPrettierのようなフォーマッターの機能を1つのツールで提供しています。設定ファイルも`biome.json`の1つにまとまるので、リンターとフォーマッターのルールが競合する問題を考えなくて済みます。`biome check --write`の1コマンドでリントとフォーマットを同時にこなせるのが便利です。

## インストール

```bash
npm install --save-dev @biomejs/biome
```

インストール後、設定ファイルを初期化します。

```bash
npx @biomejs/biome init
```

`biome.json`が生成されます。

## Astro+Svelteで使う時の注意点

Astro+SvelteのプロジェクトでそのままBiomeを使おうとすると、2つの問題にぶつかります。

### ① Svelteのテンプレート変数が「未使用」と怒られる

何も設定しないと、以下のような`.svelte`ファイルを書いた時に、`name`変数に対して[`noUnusedVariables`](https://biomejs.dev/linter/rules/no-unused-variables/)の警告が出ます。

```html
<script>
let name = "Svelte";
</script>

<h1>Hello {name}!</h1>
```

`name`はテンプレートで使われているにもかかわらず「未使用変数」と判断されてしまいます。

Biome公式ドキュメントによると、この設定が無効の場合「JavaScriptまたはTypeScript部分のみを解析用に抽出し、残りのコンテンツは無視」する動作になります[^1]。テンプレート部分が無視されるため、そこで使われている変数が未使用に見えてしまうようです。

[^1]: https://biomejs.dev/ja/reference/configuration/#htmlexperimentalfullsupportenabled

対処するには、`html.experimentalFullSupportEnabled`を`true`にします。

```json
{
  "html": {
    "experimentalFullSupportEnabled": true
  }
}
```

この設定を有効にすると、ファイル内の埋め込み言語（テンプレートとスクリプト）を一貫して処理するようになり、誤検出が解消されます。

### ② HTML系ファイルがCLIで無視される

何も設定しないままCLIで`.astro`や`.svelte`ファイルを指定すると、以下のような結果になります。

```bash
$ npx @biomejs/biome format src/pages/index.astro
Checked 0 files in 616µs. No fixes applied.
format ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ✖ No files were processed in the specified paths.
  
  ℹ Check your biome.json or biome.jsonc to ensure the paths are not ignored by the configuration.
  
  ℹ These paths were provided but ignored:
  
  - src/pages/index.astro
```

「チェックしたけどファイルは0件でした」という状態です。`experimentalFullSupportEnabled: true`を設定しても変わりません。`.astro`も`.svelte`も、デフォルトではチェック対象から外れているようです。

`overrides`でこれらのファイルを明示的に対象に含めることで解決できます。

```json
{
  "overrides": [
    {
      "includes": ["**/*.astro", "**/*.svelte"],
      "formatter": {
        "enabled": true
      },
      "linter": {
        "enabled": true
      }
    }
  ]
}
```

### 2つの問題の性質の違い

①と②を並べて書きましたが、解決している問題の種類が異なります。

- **①はパーサーの問題**。`html.experimentalFullSupportEnabled`で「`.svelte`の中身（テンプレートとスクリプト）をまとめて解析せよ」と伝える設定です。
- **②はファイル検出の問題**。`overrides`で「`.svelte`や`.astro`もチェック対象に含めよ」と伝える設定です。`.astro`だけでなく`.svelte`も同様に無視されるため、両方を含めています。

## 最終的なbiome.json

上記2つの注意点を踏まえた、このブログで使っている設定ファイルです。

```json
{
  "$schema": "https://biomejs.dev/schemas/2.5.1/schema.json",
  "vcs": {
    "enabled": true,
    "clientKind": "git",
    "useIgnoreFile": true
  },
  "files": {
    "ignoreUnknown": false
  },
  "formatter": {
    "enabled": true,
    "indentStyle": "space",
    "indentWidth": 2
  },
  "linter": {
    "enabled": true,
    "rules": {
      "preset": "recommended"
    }
  },
  "javascript": {
    "formatter": {
      "quoteStyle": "double"
    }
  },
  "html": {
    "experimentalFullSupportEnabled": true
  },
  "overrides": [
    {
      "includes": ["**/*.svelte", "**/*.astro"],
      "formatter": {
        "enabled": true
      },
      "linter": {
        "enabled": true
      }
    }
  ],
  "assist": {
    "enabled": true,
    "actions": {
      "source": {
        "organizeImports": "on"
      }
    }
  }
}
```

`vcs.useIgnoreFile: true`でgitのignoreファイルを参照し、`assist.actions.source.organizeImports: "on"`でimportの自動整理も有効にしています。

## npm scriptに登録する

毎回長いコマンドを打つのは面倒なので、`package.json`にスクリプトを登録しておきます。

```json
{
  "scripts": {
    "lint:fix": "biome check --write ./src"
  }
}
```

`biome check --write`は、リントとフォーマットを同時に行い、自動修正できる問題はその場で書き換えてくれます。

```bash
npm run lint:fix
```

これだけでリントとフォーマットが一発で完了します。

## おわりに

Astro+SvelteのプロジェクトにBiomeを導入しました。ポイントは2つで、`html.experimentalFullSupportEnabled`の有効化と、`overrides`で`.svelte`と`.astro`を対象に含めることでした。どちらも設定ファイルを数行書くだけで解決できます。

1コマンドでリントとフォーマットをまとめて処理できるのは、ESLintとPrettierを別々に管理するよりシンプルで気に入っています。
